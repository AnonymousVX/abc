PART 1: THEORY
============================================================

1. AIM
To perform hyperparameter tuning on a Convolutional Neural Network (CNN) using the MNIST dataset by varying learning rate, batch size, and number of convolutional layers. The performance of different configurations is compared using accuracy, loss, and training time. TensorBoard is used to visualize training metrics.

2. DATASET: MNIST
- MNIST stands for Modified National Institute of Standards and Technology.
- It contains 70,000 grayscale images of handwritten digits from 0 to 9.
- 60,000 images are used for training and 10,000 for testing.
- Each image has a size of 28 x 28 pixels.
- There are 10 output classes (digits 0 to 9).
- Pixel values are commonly normalized before training.
- In this practical, MNIST is downloaded using torchvision.datasets.MNIST.

3. CONVOLUTIONAL NEURAL NETWORK (CNN)
A CNN is a deep learning model mainly used for image processing and image classification.
Main layers:
- Convolution layer: extracts features such as edges, curves, and patterns using filters.
- ReLU activation: introduces non-linearity by replacing negative values with zero.
- Max pooling: reduces spatial dimensions and retains prominent features.
- Flatten: converts feature maps into a one-dimensional vector.
- Fully connected layer: performs classification using extracted features.
- Output layer: produces scores for the 10 digit classes.

4. HYPERPARAMETERS
Hyperparameters are settings selected before or during model training. They are not learned directly from the training data.

A. Learning rate
- Controls the size of each weight update.
- A very high learning rate may cause unstable training or overshooting.
- A very low learning rate may make training slow.
- The practical compares 0.001, 0.01, and 0.0001.

B. Batch size
- Number of training samples processed before one optimizer update.
- Small batch size: more frequent updates, potentially noisier gradients, lower memory use.
- Large batch size: fewer updates per epoch, often smoother gradient estimates, higher memory use.
- The practical compares 32, 64, and 128.

C. Number of convolutional layers
- Determines how many levels of image features the network can learn.
- More layers can learn more complex features but may increase computation and overfitting risk.
- The practical compares networks with 2 and 3 convolutional layers.

5. MODEL TRAINING
Typical training steps:
1. Load and preprocess the dataset.
2. Create the CNN architecture.
3. Define loss function and optimizer.
4. Pass a batch of images through the model (forward pass).
5. Calculate prediction loss.
6. Clear old gradients using optimizer.zero_grad().
7. Calculate gradients using loss.backward().
8. Update weights using optimizer.step().
9. Repeat for all batches and epochs.
10. Evaluate performance on validation/test data as appropriate.

6. LOSS FUNCTION: CROSS-ENTROPY LOSS
- CrossEntropyLoss is used for multi-class classification.
- It compares the model's predicted class scores (logits) with the true class labels.
- It combines LogSoftmax and Negative Log Likelihood Loss.
- The model should output raw logits; do not apply Softmax before CrossEntropyLoss.

7. OPTIMIZER: ADAM
- Adam stands for Adaptive Moment Estimation.
- It adapts the learning rate for each parameter using estimates of first and second moments of gradients.
- It often converges efficiently and is widely used in deep learning.
- In this practical, Adam is used with different learning rates.

8. EPOCH, ITERATION, AND BATCH
- Epoch: one complete pass through the entire training dataset.
- Batch: a subset of the dataset processed together.
- Iteration: one parameter update, usually after processing one batch.
- If there are 60,000 training images and batch size is 100, there are 600 batches/iterations per epoch (if drop_last is false and the division is exact).

9. PERFORMANCE METRICS
Accuracy = (Number of correct predictions / Total predictions) x 100
- Training loss: loss calculated on training data.
- Validation loss/accuracy: used to compare configurations and tune hyperparameters.
- Test accuracy: final unbiased performance estimate on a separate test dataset, used after selecting the configuration.
- Training time: time taken to train the model.
- Lower loss and higher accuracy are generally desirable, but also consider training time and overfitting.

10. TENSORBOARD
- TensorBoard is a visualization tool for monitoring machine learning experiments.
- PyTorch uses torch.utils.tensorboard.SummaryWriter to log values.
- add_scalar() records scalar values such as loss and accuracy.
- Each experiment can use a separate log directory, such as runs/exp_A.
- TensorBoard can display metric curves and help compare configurations.
- Typical notebook commands:
  %load_ext tensorboard
  %tensorboard --logdir runs

11. EXPERIMENT CONFIGURATIONS IN THIS PRACTICAL
The notebook compares six configurations:
- exp_A: learning rate 0.001, batch size 64, 2 convolutional layers.
- exp_B: learning rate 0.01, batch size 64, 2 convolutional layers.
- exp_C: learning rate 0.0001, batch size 64, 2 convolutional layers.
- exp_D: learning rate 0.001, batch size 128, 2 convolutional layers.
- exp_E: learning rate 0.001, batch size 32, 2 convolutional layers.
- exp_F: learning rate 0.001, batch size 64, 3 convolutional layers.
Number of epochs: 10.
Optimizer: Adam.
Loss function: CrossEntropyLoss.
Dataset: MNIST.
Architecture: configurable CNN.

12. IMPORTANT METHODOLOGICAL POINT
For a sound experiment:
- Split the original training data into training and validation sets.
- Train using the training set.
- Compare hyperparameters using validation performance.
- Do not repeatedly use the test set to select the best hyperparameters.
- After selecting the best configuration, evaluate it once on the untouched test set.
This avoids test-data leakage and gives a more reliable estimate of generalization performance.

13. COMMON PYTORCH FUNCTIONS
- model.train(): sets model to training mode.
- model.eval(): sets model to evaluation mode.
- torch.no_grad(): disables gradient calculation during evaluation.
- optimizer.zero_grad(): clears gradients from the previous update.
- loss.backward(): calculates gradients by backpropagation.
- optimizer.step(): updates model parameters.
- model.parameters(): returns model parameters.
- DataLoader: loads data in batches.
- transforms.Normalize(): normalizes image tensors.
- SummaryWriter: writes TensorBoard logs.

14. POSSIBLE OBSERVATIONS
- A learning rate that is too high may make loss fluctuate or prevent convergence.
- A learning rate that is too low may require more epochs to learn effectively.
- Batch size affects update frequency, memory use, and training behavior.
- A deeper CNN may learn richer features, but can take more time and may overfit.
- The best configuration is the one that balances validation performance and training cost; it should not be assumed in advance.
- Actual accuracy and timing depend on hardware, random initialization, data split, and software versions.

IMPORTANT DIFFERENCE QUESTIONS

Q111. Differentiate training data and validation data.
Ans. Training data is used to update model weights. Validation data is used to evaluate configurations and tune hyperparameters without updating weights.

Q112. Differentiate validation data and test data.
Ans. Validation data is used during model selection. Test data is kept separate and used for final evaluation after selecting the model.

Q113. Differentiate loss and accuracy.
Ans. Loss measures the magnitude of prediction error according to a loss function. Accuracy measures the proportion of correct class predictions.

Q114. Differentiate learning rate and batch size.
Ans. Learning rate controls the size of parameter updates. Batch size controls the number of samples processed before each update.

Q115. Differentiate epoch and iteration.
Ans. An epoch is one full pass through the training dataset. An iteration is one update based on a batch.

Q116. Differentiate shallow and deep CNN.
Ans. A shallow CNN has fewer layers and generally lower computational cost. A deeper CNN can learn more complex hierarchical features but may need more computation and regularization.

Q117. Differentiate parameter tuning and hyperparameter tuning.
Ans. Parameter tuning through training learns weights and biases from data. Hyperparameter tuning selects settings such as learning rate and batch size.

Q118. Differentiate CPU and GPU training.
Ans. CPU training uses general-purpose processor cores. GPU training uses many parallel processing units and can accelerate deep learning workloads.

Q119. Differentiate SGD and Adam.
Ans. SGD updates parameters using gradients, often with a fixed learning rate. Adam adapts updates using moving averages of gradients and squared gradients.

Q120. Differentiate classification and regression.
Ans. Classification predicts discrete categories, while regression predicts continuous numerical values.
